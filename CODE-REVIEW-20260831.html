P1功能正确性 —— 会产生错误数据或失效功能

P1-1自选"孤岛"：搜索加入的自选永远不刷新app.js · fetchAllQuotes / renderWatchlist

现象：轮询全集只有 TENCENT_SYMS + EM_SECIDS + CRYPTO_FEATURED（约 50 个 symbol）。用户从搜索进入任意一只冷门股详情页点 ★（symbol 形如 EM:1.603xxx），该 symbol 不在轮询集合里，自选页卡片永远走占位分支显示 --，且 refreshDetailQuote 不写 Cache，连缓存兜底都没有。

影响：自选核心功能对"宇宙外"标的完全失效，用户无感知。

修复：fetchAllQuotes 时把 Store.watchlist.all() 的 symbol 并入轮询（tencent 前缀的走腾讯批请求、EM: 走 secid 批请求）；同时 watchlist 存 {symbol, tencent, secid} 以便直接分组，并在 refreshDetailQuote 成功后补 Cache.set。

P1-2降级圆点与 ★ 星标视觉重叠，且修正它的 CSS 是死规则style.css:191 · app.js cardHTML

现象：.degrade-dot 绝对定位在卡片右上角 top:10px; right:10px，而 ★ 按钮也在右上角（qc-head 内）。修正规则 .qc-head .star + .degrade-dot { right: 34px } 要求圆点在 qc-head 内部且是 star 的兄弟节点——但 DOM 里圆点是 <article> 的直接子元素、在 qc-head 之外，选择器永不命中。

影响：每次出现降级角标时，圆点压在星标上，两者都看不清。

修复：卡片里 ★ 恒存在，直接把 .degrade-dot 默认改为 right: 34px（或挪进 qc-head 用 flex 布局），删掉死规则。

P1-3heatVia / heatCachedAt 单变量被 A股与加密两个视图共享app.js:338/341/356/359/395/483

现象：state.heatVia 只有一个槽位，loadHeatCN 和 loadHeatCrypto 都往里写。后完成的加载会覆盖先完成的状态——例如 A股走了缓存、加密走主源，则热力图 A股视图和情绪页的"数据来源"标注会错误显示"实时"；反之亦然。

影响：降级透明度造假——用户看到的来源标注不可信，违背项目"降级必须可见"的设计原则。

修复：改为 state.heatVia = { cn: null, crypto: null } 按模式存取，drawHeat/renderMood 读对应槽位。

P1-4北交所 920 新代码段两处漏判breadth.js:28 · app.js tencentOfSecid

现象：① limitOf 只认 /^(8|4)/ 为北交所（±30%），2024 年起启用的 920 段新股会按主板 ±10% 误判涨跌停家数；② tencentOfSecid('0.920xxx') 返回 sz920xxx（正确应为 bj920xxx），从热力图点进 920 段个股详情后，腾讯报价/K线/分时整条链全断，只剩东财不可达的备源 → 永远"暂无该周期数据"。

影响：情绪页涨跌停统计失真（920 段封板股漏计）；920 段个股详情页图表不可用。

修复：limitOf 增加 /^92/ → 30；tencentOfSecid 对 0.92xxxx 特判返回 'bj' + code；并在 breadth.test.mjs 补 920 段断言。

P1-5产业链行情 10s 轮询无视当前视图，白跑请求app.js:1134-1138

现象：schedule('heat') 有 view !== 'market' 门控、schedule('mood') 有 view !== 'mood' 门控，唯独 schedule('chain') 没有——即使用户从不打开产业链 tab，也每 10s 拉取 163 只成分股行情（腾讯 3 个分块请求），整天挂着就是上万次无效请求。

影响：浪费带宽与上游配额，也提高被上游限流封 IP 的风险（连累其它东财/腾讯功能）。

修复：加 if (state.view !== 'chain') return; 门控；切到 chain tab 时立即补一次（setTab 已有对应分支）。

P1-6搜索无竞态守卫：慢的旧响应覆盖新输入app.js:1023-1040

现象：详情图有 chartGen 防竞态（P1-6 已修的先例），但 doSearch 没有。快速连续输入"茅台"→"腾讯"时，若"茅台"的 JSONP 响应慢于"腾讯"，下拉框最终显示的是旧关键词的结果。

修复：加 state.searchGen 代次号，响应落地前比对；或干脆在发起新请求时 abort/忽略旧回调。

P1-7触屏长按浮层定时器未随拖动取消app.js:436-443

现象：touchstart 起 350ms 定时器弹浮层，但 touchmove 里不清除。用户单指拖拽平移热力图超过 350ms，拖到一半浮层突然弹出，且浮层数据是起始点而非当前点。

修复：treemap 的 touchmove 已把 dragged 置真，bindHeatHover 侧在 touchmove（位移 > 阈值）时 clearTimeout(lp)。

P1-8外汇/商品/宏观详情页 K 线永远为空——可用的 delay 镜像没有被用上eastmoney.js:143-160 · worker.js:24

现象：klineFor 对 119/133/101/102/103/171 系列 secid：腾讯映射返回 null，备源 push2his.eastmoney.com 直连不可达（README 已实测）→ 六类标的详情页图表永远"暂无该周期数据"。但 worker.js 白名单里早已躺着 push2hisdelay.eastmoney.com——与救活了报价的 push2delay 同源的延时镜像，代码里没有任何地方用它。

影响：外汇宏观 tab 下每张卡片点进去都是空图，功能名存实亡。

修复：东财 getKline 先试 push2hisdelay.eastmoney.com（大概率直连可用，与 push2delay 同理），失败再退 push2his + 代理；成功后在 live.test 补一条外汇 K 线断言。

P2健壮性 / 性能 —— 现在能跑，但埋着雷

P2-1lightweight-charts 走 unpkg 且不锁版本、无本地兜底index.html:211

现象：https://unpkg.com/lightweight-charts/dist/... 拉的是 latest。v5 曾改 API（charts.js 已做 v3/v4/v5 兼容，说明踩过坑），未来 v6 再改一次详情页全废；unpkg 被墙/抽风时同样全废，只剩"暂无数据"。

修复：锁版本号（如 lightweight-charts@4.2.0），更彻底的做法是下载 standalone 文件到 lib/ 本地引用——符合项目"零依赖、file:// 可跑"的定位，还顺便支持离线。

P2-2热力图每帧 2 次 getComputedStyletreemap.js:191, 83-90

现象：paint() 每次执行都调 refreshColors()（读 documentElement + body 两次计算样式）。hover 移动时 setHover → draw → paint，等于 60fps 强制样式重算，5500 块画布上这是可感知的耗电/掉帧来源。

修复：颜色缓存到模块级变量，仅在 onUpdownChanged（app.js 已在调 Treemap.refreshColors）与首次绘制时刷新，paint 内不再读。

P2-3详情页同一份日K发两遍请求app.js:625 · loadDetailInsight

现象：openDetail 并行 4 个任务，其中 loadDetailChart（period=day 时）与 loadDetailInsight（画像必须取日K）各自独立调 klineFor(t,'day')，同一接口同一参数发两次。

修复：以 symbol+period 为 key 做 in-flight Promise 去重（或 insight 复用 chart 已取到的 klines），省一半详情页请求。

P2-4缓存兜底仅存内存，页面一刷新降级链最短环断裂utils.js Cache

现象："主源→备源→缓存"是本项目核心卖点，但 Cache 是 new Map()——刷新页面后缓存清空，此时若主备源恰好都挂，直接空白。localStorage 只存了自选和设置。

修复：关键键（q:* 最近一轮、heat:cn、news、report:*）配额化持久化到 localStorage（带时间戳、超龄丢弃、总量封顶 ~1MB 防 QuotaExceeded）。

P2-5页脚状态灯颜色跟随红绿切换，语义反转style.css:556-557

现象：.status-ok { color: var(--down) }、.status-bad { color: var(--up) }。默认红涨绿跌下"正常=绿、降级=红"碰巧正确；用户切到绿涨红跌后 token 互换，"正常"变红、"降级"变绿，语义完全反了（研报评级/情绪分档用涨跌色是设计意图，状态灯不是）。

修复：状态灯改用独立 token（如 --ok / --warn）不参与红绿互换。

P2-647+ 张卡片常驻 will-change: transformstyle.css:164

现象：每张 .quote-card 常驻 will-change: transform，浏览器为每张卡维持独立合成层；自选页+产业链展开时轻松破百层，白白吃显存。

修复：改为 .quote-card:hover { will-change: transform } 或干脆删掉（translateY(-4px) 的 hover 动效不需要预提升）。

P2-7patchCards 每轮无条件写 DOMapp.js:290-294

现象：价格文本有判等（node.textContent !== txt），但 .qc-row 两个 span 的 class 与 textContent 每轮无条件重写——47 卡 × 每 10s，绝大多数时候值根本没变，纯 DOM churn。

修复：写入前先比较，className 也可缓存上一次的 cls 再决定动不动。

P2-8全市场分页并发无 code 去重eastmoney.js getFullMarket

现象：按 fid=f3（涨跌幅）排序拉 55 页，盘中行情跳动时相邻两页之间个股会位移——同一只股可能出现在两页里（重复），也可能跳过（漏行）。当前直接 concat，重复股会让热力图面积虚增、情绪计数虚高。

修复：汇总后用 Map(code → row) 去重再返回；漏行无解但可接受，去重是必须的。

P2-9情绪卡片同屏两个"上涨占比"口径breadth.js:77,81 · app.js:490

现象：情绪指数 score = up/(up+down)（剔平盘），而旁边标注的"上涨占比"upRatio = up/total（含平盘）。同一屏两个相近但不同的数字，用户会困惑哪个才是分数的依据。

修复：统一口径（建议标注直接显示 up/(up+down) 的百分比），或文案改成"上涨占全市场比"以明示差异。

P3打磨 / 工程 —— 不影响正确性，做了一身轻松

P3-1渲染期热点里的重复开销app.js cardHTML

① reduceMotion() 每张卡调 2 次 → 一次整墙渲染约百次 matchMedia，应缓存为模块级布尔 + change 监听；② Store.watchlist.has() 内部每次 JSON.parse(localStorage)，renderWatchlist 渲染 N 张卡就解析 N 次，应在渲染前取一次数组转 Set 传入。

P3-2返回卡片墙时入场动画整体重播app.js setTab → renderCardWall

从详情页返回、切设置、切 tab 都会 renderCardWall 全量重建 + stagger-in 重播。建议：仅 tab 真正切换时播放 stagger，返回/设置变更走 patchCards 或不带动画的重建。

P3-3死代码与小瑕疵打包多处

① utils.js fetchGBK 导出但零调用（request({gbk:true}) 已覆盖），删；② index.html 两处内联 style="margin-top:32px" 应入 CSS；③ 无 favicon（每次打开 404 一次），可加内联 SVG data-URI；④ 建议加 <meta name="color-scheme" content="dark"> 让滚动条/表单控件跟深色；⑤ selftest 里 padEnd(8) 对中文等宽无效、newsVia 为 null 时打印字面 "null"。

P3-4squarify / hitTest 的微优化（非必须）treemap.js

① rowRatio(row.concat(v), …) 每试一个候选就复制一次数组，5500 块布局约百万级元素拷贝，可改原地 push/pop；② hitTest 线性扫 5500 块/mousemove（16ms 节流下实测可接受），想做的话按 x 排序二分或网格索引。

P3-5首屏瀑布可并行app.js init

await fetchAllQuotes() 与 await loadHeatCN() 串行，二者无依赖。并行后首屏热力图可提前 1-3s 出现（55 页分页抓取是大头）。

P3-6新闻/研报定时器无条件运行app.js:1132-1133

用户从不打开新闻/研报 tab 时，60s/10min 轮询照跑。可改为首次进入 tab 才启动对应 schedule（数据已有懒加载分支，只差定时器门控）。

P3-7无障碍两处打磨index.html / app.js

① role="tablist" 的 tab 缺 aria-controls 与对应 tabpanel 关联；② 搜索框缺 aria-expanded/aria-activedescendant，键盘上下移动时读屏器不知道高亮项；③ 设置弹层无焦点圈定（focus trap），Tab 键会跑到遮罩后面的内容上。

P3-8静态知识层无新鲜度机制masters.js / explain.js / industry-chains.js

47 条标的属性、163 只成分股、大师文本都是人工维护——公司改名、成分股被 ST、业务叙事变化都不会有人知道该更新了。建议：文件头加"数据截止：2026-08"注释，并在自检区输出该日期，超过 3 个月就在自检区提示复核。

P3-9worker.js 无速率限制worker.js

域名白名单防了"开放代理"，但任何人都可以借你的 worker 高频打白名单内的上游（腾讯/东财/币安），额度耗尽或被上游封的是你的 worker IP。README 加一句风险提示即可；要真防可上 Cloudflare Rate Limiting 规则。

P3-10_test 无一键全跑入口_test/

6 个测试文件要敲 6 条命令。加一个 _test/run-all.mjs 顺序 spawn 并汇总退出码，README 改成一条命令；live 类测试注明需要网络与非交易时段容差。

P3-11功能增强建议（非缺陷，按需采纳）—

① 情绪指数历史曲线：每次 loadMood 把 {ts, score} 存内存（或 localStorage），情绪页加一条当日 sparkline，比单点数字有用得多；② 两市成交额目前显示"18442.78 亿"，可格式化为"1.84 万亿"；③ 详情页打开时同步 document.title 为标的名，切走还原。
